# マイログ

プロジェクトの実行中に、日々の作業(タスク・時間・進捗・進捗率)、問題と依頼、テストの結果・TRL・TPM を 1 つのテキストに書き足していくブラウザアプリです。
`index.html` 1 ファイルだけで動き、インストールやアカウントは要りません。外部のサービスを読み込まず、書いた内容をどこにも送信しません。

工数を把握することよりも、問題が起きていないか(詰まっていないか、依頼が放置されていないか)を早く拾い出すことに重点を置いています。

- 1 人 1 ファイルで、プロジェクトの期間を通して同じファイルに書き足す
- [プロジェクト計画](https://plan.sapp.jp)の計画書(`.plan`・`.plans`)を読み込むと、タスク名・機能名・MOP の文を照合し、打ち間違いを見つける。名前と MOP の文は補完で選べる
- 計画が途中で変わっても、記録の日付に合う版の計画で照合する。集計では、移動したタスクの前の記録も今のタスクの記録として数える(名前を変えたタスクは追わない。名前を変えたり削除したりしたタスクの記録は、名前の後ろに「(計画から削除)」を付けて別の行にする)
- テキストに直接書くほか、画面からも書ける(表の行を押して記録を直す、「記録を追加」で記録を追加する、タスクの進捗や問題の解決を今日の記録に書く)。「AI で記録」で、生成 AI に質問してもらいながら今日の記録を作るためのプロンプトをコピーできる(人の名前は伏せる。AI には自分で貼る)。テキストが正本で、画面の操作はテキストの書き換えになる
- 計画の中の自分を中心に見せる: 担当のタスクを、実行中・遅延・問題発生・開始予定日を過ぎた未着手・開始予定日がまだ先・完了に分けて並べ、計画の日程と記録(進捗・進捗率・時間)を並べて見られる。ガントチャートで、予定と実際に作業した日を見比べられる
- 記録の形から問題の兆候(記録の途絶、問題の長期化、終了予定日の超過、進捗の停止 など)を規則で拾い出し、サマリーの「要確認」に出す
- 今週の予定、計画の変更のうち自分に関係するもの(作成者・確認者・日程)、担当するテスト項目(MOP)を出す
- 週ごとの作業時間と記録のカレンダー、1 週間の記録を 1 枚にまとめた週のまとめ、テストの記録・TRL・TPM の推移を表にする
- テキスト(.mylog)で保存。表は 1 つずつ SVG・PNG・PDF で保存でき、タブ区切りでコピーできる

## ほかのアプリとの関係

マイログは、[プロジェクト計画](https://plan.sapp.jp)の計画書(`.plan`・`.plans`)を読んで使います。計画書がなくても記録は書けますが、名前の照合、担当のタスク、計画を使う兆候、今週の予定、計画の変更は出ません。計画書は読むだけで、書き換えません。

チーム全員のマイログを集めて、集計と依頼の突き合わせをするのは、[プロジェクト分析](https://projalysis.sapp.jp)の作業分析です。

どのアプリをどう組み合わせるかは、プロジェクトを運営する人が決めます。マイログを使う組み合わせの例:

- 計画とマイログ: 各自がマイログに記録し、自分の担当のタスクの進み具合を見る
- 3 つとも: 各自のマイログをプロジェクト分析に集めて進み具合と問題の兆候を見、反映候補をもとに計画書を直して新しい版を保存する

## 使い方

公開版は https://mylog.sapp.jp で使えます。
ダウンロードした `index.html` をブラウザで直接開いても使えます。

1. 公開版か `index.html` を、ブラウザ(Edge・Chrome など)で開きます。
2. 「計画書を追加」で、プロジェクト計画の `.plan`(または `.plans`)を読み込みます(なくても書けます)。
3. 左の欄に記録を書くか、「記録を追加」で日付と名前を選んで記録を追加します。書き方は画面上部の「書き方」ボタンで見られます。
4. 画面上部の「ビュー」で、サマリー・タスク・ガントチャート・週のまとめ・作業時間・テスト・TRL・TPM を切り替えます。表の行を押すと、その記録の行を選び、右下の編集パネルが出ます。

| ビュー | 内容 |
|---|---|
| サマリー | 担当のタスクの区分ごとの件数の表(実行中、遅延、問題発生、開始予定日を過ぎた未着手、開始予定日がまだ先、完了。タスクは WBS 番号だけ)。続いて今週の予定、計画の変更(照合に使える最後の 2 つの版を比べた、作成者・確認者・日程の変更と移動)、未解決の問題、要確認(問題の兆候)、出した依頼、確認するタスク |
| タスク | 計画で自分が担当のタスクを、区分ごとに分けた表(サマリーの区分に、完了したタスクを加えたもの。対応が要る区分は実行中のすぐ下にまとめる)(予定の期間・始めた日・日数・作業日数・計画の進捗・今の進捗・進捗率・合計時間。確認を頼んで返事を待っているタスクは、今の進捗に「(確認待ち)」と添える)。確認者のタスクと、担当外の記録も並べる |
| ガントチャート | 担当のタスクを計画の日程で描き、時間を書いた日に点を打つ |
| 週のまとめ | 選んだ週(ビューの上の帯で選ぶ。既定は今週)の作業時間・進捗と進捗率の報告・問題と解決・依頼と返事・メモ・テストを 1 枚にまとめる |
| 作業時間 | 週ごとの作業時間の表と図、記録のカレンダー(日ごとの時間) |
| テスト・TRL・TPM | 担当するテスト項目(担当のタスクの対象が実現する機能の MOP と、最後のテストの結果)、テストの記録、TRL・TPM の推移 |

初めて開いたときは空です。「例を読み込む」を押すと、カレンダーアプリの開発の例(マイログと、2 つの版の計画書)が入ります。例の日付は、読み込んだ日がプロジェクトの途中になるようにずらして入れるので、いつ読み込んでも、すべての表に例が出ます。計画書の一覧は例の計画書の 2 つの版に入れ替わります(計画書のファイルは消えません)。2 回目からは、前に編集していた内容の続きが開きます。

## 書き方

```
version: 2026-04-30
by: 青木
week: wed

- 2026-04-27
  - 通知用APIの実装 hours: 3 status: doing progress: 40 ask: 井上 note: メール送信の設定を相談した
- 2026-04-28
  - 通知用APIの実装 hours: 3 status: blocked issue: SMTP の認証が通らない
  - 登録確認メール test: ng mop: 予定の登録から 1 分以内にメールが届く
  - 登録確認メール trl: 2
```

- 日付の行は字下げなしの `- YYYY-MM-DD`、記録の行は字下げして `- 名前 予約語: 値` と書きます。
- 名前は計画のタスク名か機能名です。同じ名前が計画に 2 つあるときは `親::子` と書きます。
- `//` から行末までは注です(行頭か、空白の後の `//` だけ)。

### 設定の行

| 設定 | 必須 | 書くもの |
|---|---|---|
| `version:` | | 最後にファイルとして保存した日(`YYYY-MM-DD`)。1 行目にだけ書ける。上書き保存・別名で保存のときにアプリが書く |
| `by:` | 必須 | 記録者(このマイログを書く人)の名前 |
| `week:` | | 週の始まりの曜日(`mon`〜`sun`)。省略したら `mon` |

### 属性

| 属性 | 名前 | 意味 |
|---|---|---|
| `hours:` | タスク | その日にかけた時間 |
| `status:` | タスク | その日の時点の進捗(`todo`・`doing`・`done`・`blocked`) |
| `progress:` | タスク | その日の時点の進捗率(0〜100。自分の感覚の値でよい)。`status:` を書かなければ、100 なら完了、100 未満なら実行中とみなす |
| `review:` | タスク | 確認を依頼した相手 |
| `reviewed:` | タスク | 依頼された確認をした結果(`ok`・`ng`) |
| `trl:` | 機能 | その日の時点の TRL |
| `tpm:` | 機能 | その日に測った TPM の値 |
| `test:` | 機能 | テストの結果(`ok`・`ng`)。テストした MOP の文を `mop:` で組にして書く |
| `issue:` | どちらでも | 起きている問題(同じタスク・機能か同じ名前に、後で `solved:` を書くまで未解決) |
| `solved:` | どちらでも | 問題が解決したこと |
| `ask:` | どちらでも | 質問した相手 |
| `answered:` | どちらでも | 受けた質問に答えたこと |
| `note:` | どちらでも | メモ |

### 書けないもの(構文エラー)

見出し(`#`)、番号付きのリスト、`*`・`+` のリスト、太字、説明の文、コードブロックは書けません(`**` と `__` は、`note:`・`issue:`・`solved:`・`answered:`・`mop:`・`tpm:` の文には書けます)。課題の詳しい内容、AI の利用状況、次回の計画は、マイログの外に書きます。

## 画面から書く

| 操作 | 内容 |
|---|---|
| 表の行を押す | その記録の行を選び、右下の編集パネルに名前と属性を出す。欄を書き換えて Enter(または欄から離れる)で、その行を書き換える。欄を空にすると属性を消す。「この記録を消す」で行を消す |
| 記録を追加 | 日付(既定は今日)と名前(計画のタスク・機能から選べる)を選び、時間・進捗などを書いて「追加」で、その日付の記録の最後に足す。日付の行がなければ、日付の並びが崩れない場所に足す。名前が機能なら、テスト・MOP・TRL・TPM の欄も出る |
| タスクのビューの行を押す | 「今日の記録」の欄で、進捗・進捗率・時間を今日の記録に書く。今日の記録に同じタスクの行があれば(名前の書き方によらず)その行に、なければ行を足す(過去の記録は変えない)。進捗率・時間の欄を空にすると、今日の記録からその属性を消す |
| サマリーの「未解決の問題」・要確認の S2 の行を押す | 「解決を記録」で、今日の記録に `solved:` を書く(今日の `issue:` の行には足さず、別の行にする。同じ行の `solved:` では問題が閉じないため) |
| AI で記録 | 生成 AI に質問してもらいながら今日の記録を書く手順と、「プロンプトをコピー」のボタンを出す。コピーしたプロンプトを自分で AI に貼り、AI が出した記録の案を自分で確かめてから、テキストの最後に貼る。このアプリは AI に何も送らない。プロンプトでは人の名前を伏せる(自分は「本人」、ほかの人は「メンバーA」など。対応はパネルに出す) |

「AI で記録」のほかは、どの操作もテキストの書き換えで、テキスト欄で Ctrl+Z 1 回で戻せます。エラーになる書き換え(タスクと機能の属性を同じ行に書く、など)は書き込まず、理由を編集パネルに出します。テキストにエラーがある間は、画面から書けません。

## 要確認(サマリーのビュー)

| 番号 | 兆候 | 規則(既定の値) |
|---|---|---|
| S1 | 記録の途絶 | 完了していない担当タスクがあるのに、7 日記録がない |
| S2 | 問題の長期化 | `issue:`・`blocked` が 7 日以上解決していない |
| S4 | 日数の超過 | 作業日数(時間を書いた日の数)が計画の日数を超えたのに、完了していない |
| S5 | 終了予定日の超過 | 終了予定日を 1 日過ぎて、完了していない |
| S6 | 手戻り | 完了と報告したタスクが、後で実行中か問題発生になった |
| S7 | 計画にない作業 | 週の時間の 50 % 以上が、計画にない作業 |
| S8 | 進捗の停止 | 進捗率が 14 日以上変わっていない |
| S9 | 確認の抜け | 計画で作成者以外の確認者のいるタスクを、確認の依頼なしに完了にした |

日数などの値は「設定」で変えられます(このブラウザに残し、ファイルには書きません)。今日は表示した日の日付です。S1・S4・S5・S7・S9 は、計画書を読み込んだときだけ判定します。

## 保存と読み込み

| 操作 | 内容 |
|---|---|
| 上書き保存(Ctrl+S) | 左の欄のテキストを、開いているファイルに上書きする。まだファイルがないときは保存先を選ぶ |
| 別名で保存 | 保存先とファイル名を選んで、テキスト(.mylog)を保存する。名前の候補は `by:` の名前(例: `青木.mylog`) |
| 表の題の右の「コピー」 | 表をタブ区切りの文字でコピーする |
| 図・表の題の右の「SVG」「PNG」 | その図・表 1 つだけを画像で保存する(表には題を入れない) |
| 図・表の題の右の「PDF」 | その図・表 1 つだけを、同じ大きさの紙(余白なし)で印刷する |
| 印刷 / PDF | ビューをすべて、縦向きのページに印刷する(長い表は行で区切る) |
| 開く / ドラッグ & ドロップ | `.mylog` は開く。`.plan`・`.txt`・`.plans`・プロジェクト計画の版 0.30 までの `.svg` は計画書の一覧に足す(`.plans` の中のマイログは読まない) |
| 計画書を追加 | `.plan`・`.txt`・`.plans`・`.svg` を計画書の一覧に追加する。計画書は読むだけで、書き換えない |
| 新規 | テキストを空にする(計画書の一覧は残す) |

保存すると、1 行目の `version:` がその日の日付になります(内容が変わったときだけ。プロジェクト計画と同じ)。
編集中のテキストと計画書の一覧は、このブラウザの `localStorage` にも自動で保持されます(どこにも送信されません)。残したいマイログは、必ずファイルに保存してください。

## 動作環境

Edge・Chrome などの最近のブラウザで動きます。印刷 / PDF と、図・表の題の右の「PDF」は、Chrome・Edge で使ってください。ダウンロードした `index.html` は、ネットに接続しなくても動きます。

## ファイル

| パス | 内容 |
|---|---|
| `index.html` | アプリ本体(これ 1 つで動く) |
| `dev/core.js` | プロジェクト計画の計算部の写し(計画書を読むのに使う。書き換えない) |
| `dev/logcore.js` | マイログの解析・照合・兆候・表の描画。Node でも `require('./dev/logcore.js')` で読める。プロジェクト分析はこれを写して使う |
| `dev/ui.js` | 画面の処理 |
| `dev/help.html` | 画面の「書き方」の中身 |
| `dev/build.py` | `index.html` を組み立てる(`python3 dev/build.py`)。`python3 dev/build.py sync` でプロジェクト計画(`~/projects/plan`)の `dev/core.js` から写し直し、`check` で同じかを調べる |
| `docs/spec.md` | 仕様書 |
| `test/logcore_test.cjs` | 計算部の検査(`node test/logcore_test.cjs`)。`test/sample.mylog`・`test/sample.plan`・`test/sample_old.plan`(計画書の前の版)は例と検査の入力 |
| `test/ui_test.py` | 画面の検査。Python の playwright と Chromium で動かす(`python3 test/ui_test.py`) |
